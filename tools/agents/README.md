# tools/agents

Account-agnostic helpers for the hive (AT mode; rules: `docs/agents/hive.md`, team preferences: `docs/agents/team-memory.md`).
Every script sources `hive-env.sh`, which loads `hive.conf` (repo root), `accounts/_shared.conf`, and `accounts/<handle>.conf`
for the account named by env `HIVE_ACCOUNT` or `gh api user -q .login`, then the hive hub's values from the studio cache
(`STUDIO_REPO`): each person's 5h stop, weekly stop, auto-file and max workers (`hive/account-limits.conf`) and the studio settings
`reset_spend_hours`, `offline_hours`, `ready_ticket_min` (`hive/settings.conf`), which win over the confs. macOS first (BSD `date`/`stat`); `hive-env.sh` shims
GNU for Linux and Git Bash on Windows. Needs `gh`, `jq`, `curl`; `screen` on macOS/Linux (`windows/` replaces it on Windows).
Per-account state and secrets live in `$HIVE_STATE` = `~/.claude/hive/<repo>/<handle>/`, never in the repo.

## Core
- `accounts/<handle>.conf`: per-account settings (role, reserve, timezone, quiet hours, thresholds, display name). `_shared.conf` holds shared defaults (the hub's settings win); `example-*.conf` (triagemaster, dev, reserve) are templates, never accounts.
- `hive-env.sh`: sourced by all; resolves the account, conf and `HIVE_STATE` dir (moving a claude-autotriage `~/.claude/at/...` dir once, or copying an old pf-* hive state dir per hive.conf `LEGACY_STATE` once); helpers `hive_budget_ok` (own weekly stop), `hive_worker_target` (0 at a stop or while the pace governor says AHEAD, else the max workers), `hive_pace_now`, `hive_limits`, `hive_studio_settings`, `hive_tm_mode`, `hive_quiet`, `hive_is_triagemaster`, `hive_beacon`, `hive_usage_backfill`, `hive_review_passed`, `hive_mark_review`, `hive_pid_alive`, `hive_keepalive_running`, `hive_control_panel`, `hive_guard`, `hive_display_name`, `hive_fmt`, `hive_mtime`.
- `hive-at-mode.sh`: prints `AT·on pace`, `AT·ahead`, `AT·behind` (the pace governor's state) or `MT` (with a studio, MT = switched out in the hub); `hive-at-mode.sh AT|MT` switches only without a studio file.
- `hive-ticketmaker.sh`: prints this game's ticket-maker mode, `full`, `suggestions` or `off` (rule 11); the status line shows `·TM sugg` or `·TM off`. With a studio the owner sets it per game in the hub (Hive settings, the studio's `hive/ticket-maker.conf`); without one, `hive-ticketmaker.sh full|suggestions|on|off` sets a local fallback (on = full, off = suggestions).
- `hive.sh status [--short] [--cached]`: one screen of the whole hive: every account's online state, role, usage, agents, claims, queue and PRs, then fires, unhandled Discord reports and owner decisions. `--short` is what "status" in the dev channel replies with.
- `hive-join.sh`: the SessionStart hook (install.sh merges it into `.claude/settings.json`): reminds the session to read team-memory.md, restarts a dead channel supervisor, prints the cached hive status. Never blocks the session. `HIVE_JOIN_NO_START=1` (tests) restarts nothing; `windows/hive-start.ps1` likewise honours `HIVE_NO_START=1`.

## Watchers and merging
- `hive-triage-watch.sh`: zero-token poller; exits with one line when Claude must act: UNTRIAGED, MYTICKET, FEATURES? PR, PEER_BEACON, DEV_IDLE, IDLE_SLOTS, PEER_QUEUE_LOW, MSG, DISCORD_BUG, DISCORD_DEV, DISCORD_APPROVED, HIVE_TAKEOVER, TM_CHECK_FAIL, MODE_MT, or a `WATCH_HOOKS` line. `--functions` sources its helpers for tests.
- `hive-watch-peers.sh`: triagemaster watcher for peer activity, stale peers and unowned tickets. Never reports a ticket another account claimed in the last 24h (channel CLAIM or `[CLAIM]` comment).
- `hive-automerge.sh`: merges green, mergeable, `review-passed` PRs, comments on conflicting ones once per head; leaves `conflict-risk` PRs to the triagemaster and `review-blocked` PRs alone. Fast-forwards the main checkout only when it is on `MAIN_BRANCH`.
- `hive-ship.sh <issue> "<title>" "<body>" [repo-name] [--refs]`: merges main into the ticket branch, runs `TEST_CMD` and the fresh-clone boot check, runs the leak check, pushes, opens (or reuses) the PR with a Resource Usage section, waits for CI and merges once reviewed. `--refs` ships a partial fix (`Refs #N.`, the ticket stays open).
- `hive-wake.sh [--ack]`: the triage wake line in plain bash for a headless session (the twin of `windows/hive-status.ps1`): supervisor states, then `WAKE <line>` with exit 10 while unhandled; `--ack` marks it handled.
- `hive-tm-check.sh [--quiet]`: triagemaster self-check (rule 19), one PASS/WARN/FAIL line per duty with the fix.
- `hive-succession.sh [--post]`: computes the current triagemaster from the beacons (rule 7) and writes it to `$HIVE_STATE/triagemaster`; `--post` sends the `TM` line.
- `hive-reserve.sh [--dry|--install]`: reserve-account supervisor (rule 5): hands tickets back while the regular devs can work, starts an unattended session (prompt: `hive-reserve-prompt.md`) for `TRUSTED_TICKET_AUTHORS` tickets when they cannot. `--install` adds the launchd job (macOS) or prints a cron line.

## Private channel and usage
- `hive-msg.sh init|send <TYPE> <text>|claim <n>|release <n>|listen|backfill|claimed <n>|heartbeat|run`: private ntfy channel between accounts (CLAIM, RELEASE, USAGE, ASK, ANSWER, INFO, FIRE, HELLO, TM), a doorbell only: verify on GitHub. Setup: `hive-msg.sh init` on one machine, share the topic out of band (never commit it; ntfy topics are public to anyone who knows the name), and each other account writes the same `HIVE_MSG_TOPIC=<topic>` line into its own `$HIVE_STATE/msg.conf` (optional `HIVE_MSG_SERVER`, default `https://ntfy.sh`). Keep `hive-msg.sh run` alive (`windows/hive-supervise.sh msg`, which `hive-join.sh` restarts): it listens, sends HELLO only when this account sent nothing for 60 min, and wakes the watcher with `MSG FIRE peer-silent <peer>` when a peer sent nothing of any type for 2 h. One listener and one supervisor per state dir (`msg-listen.pid`, `msg-run.pid`); a second exits at once. `hive-msg.sh status [line]` writes `msg-status.json`. Off in `SINGLE_ACCOUNT` mode.
  - **Send budget.** ntfy.sh's free tier allows about 250 messages a day per IP. `send` counts this account's sends per UTC day in `$HIVE_STATE/.msg-count`; once 70% of `HIVE_MSG_DAILY_MAX` (default 100; set it in `accounts/_shared.conf` or the account conf) is used, USAGE, HELLO and INFO are dropped and logged to `beacon.log`, while CLAIM, RELEASE, ASK, ANSWER, FIRE and TM always go out. On HTTP 429 every send pauses until now + `retry-after` (`$HIVE_STATE/.msg-backoff-until`, logged once); `msg-status.json` then carries `quota` (the until time) and the status line shows `msg:quota til HH:MM`. Other failures go to `beacon.log` with their HTTP code. Steady state is about 24 USAGE a day and no HELLO.
  - **Paid tier or self-hosted server.** Add `HIVE_MSG_TOKEN=<ntfy access token>` to `msg.conf` (and `HIVE_MSG_SERVER=https://your.server` for a self-hosted ntfy). The token goes to curl as `Authorization: Bearer` through its config on stdin, never on the command line; never commit it (`hive-msg-leakcheck.sh` checks for it). No code change is needed.
- `hive-ask.sh <account> "<question>" [timeout]`: asks another machine with a `[q<id>]` tag and waits for the matching ANSWER (rule 17).
- `hive-msg-leakcheck.sh [dir]`: exit 1 when the channel topic, its `HIVE_MSG_TOKEN` or the Discord token is in tracked files, the staged diff or unpushed commits; `hive-ship.sh` runs it before every push.
- `hive-voice.mjs`: the hub voice runner (docs/hub/voice-protocol.md). It runs where `hive.conf` (or `$HIVE_STATE/hub.conf`) sets `HUB_URL`, and signs in with the member's own `gh` login, so no secret is copied between machines. After hello it reports the machine's game channel topics to the hub. `windows/hive-supervise.sh voice` keeps it alive on every OS, and `hive-join.sh` restarts that supervisor when its `voice-status.json` goes stale. Machines without a `HUB_URL` run no runner.
- `hive-control.sh state`: the hub's control frames. `hive-voice.mjs` runs it for an allowlisted `control` frame (none today: the ticket-maker mode moved to the studio file, so every frame is refused), and anything else exits 2. It prints `{ticketmaker}`. `hive-join.sh` records each project's checkout in `$HIVE_STATE/checkout`, so one runner can reach every project on the machine.
- `hive-beacon.sh`: sends this account's `USAGE` beacon (the only beacon; nothing goes to GitHub) when it is due: the 5h or 7d % moved 5 points, the 5h reset moved, or `agents=` changed, else hourly; never within 10 min of the last. Everything that beacons goes through this gate.
- `hive-usage.sh [--no-beacon]`: refreshes the usage snapshot from Anthropic's usage endpoint for machines with no status line, then runs the beacon gate.
- `hive-pace.sh [state|start|target|explain|max|log|tune|lastwin|report]`: the pace governor (`start` = `state`, but refused in a control-panel session; run it before every worker start) (issue #274, zero tokens, no `claude` call): prints AHEAD / ON_PACE / BEHIND from the usage snapshot so each machine uses its 5h window in exactly 5 hours (weekly pace, on a line scaled to the account's weekly stop, wins); the beacon tick logs `pace-log.csv`, closes each window into `pace-windows.csv` and self-tunes `pace-tuning.conf`; `report` shows every account's pace from the inbox. See hive.md, Pace governor.
- `statusline.sh`: Claude Code statusLine command (line 1 shows `5h N% (r time) / T% pace`); saves the usage snapshot, runs the beacon gate every 5 min, and shows `msg:quota til HH:MM` while ntfy's quota blocks the channel.
- `hive-status-refresh.sh`: background cache for status-line lines 2+; run by `statusline.sh`.
- `hive-rate.sh`: source it to set `HIVE_RATE` / `HIVE_WEEK` for PR bodies.

## Discord (optional, `DISCORD=1`; never in private mode)
- `hive-discord-env.sh`: sourced by the Discord scripts: reads `$HIVE_STATE/discord.conf` (`HIVE_DISCORD_TOKEN`, `HIVE_DISCORD_ID_<account>`) and wraps curl.
- `hive-discord-bugs.sh [--dev] check|read|reply <id> <text>|ack <id> <reason>|approvals|status`: the report channels (rule 18); public reports wait for a ✅, dev-channel reports are pre-approved.
- `hive-discord.sh`: the server for any account when its user asks (rule 20): channels, read, watch, post, roles, members, create, role-add, api.
- `hive-failover.sh check|takeover <id>`: takes over the triagemaster role when a dev-channel message waits 10 minutes (rule 21).
- `hive-dev-idle-alert.sh <account> <minutes> "<what waits>" [--post]`: the DEV_IDLE message, with an opt-in ping.

## Session and outbox
- `hive-keepalive.sh [--print-prompt|--nudge <text>]`: keeps the background AT session alive in `screen`; fills `hive-session-prompt.md` from config. A session parked on a usage limit is nudged to continue once it has been idle `STALL_MINUTES` (default 15; `hive_limit_stalled` in `hive-env.sh`). A session idle `IDLE_NUDGE_MINUTES` (default 30) with no limit and a worker target above 0 is nudged too, at most once per that interval (`hive_session_idle`). Nudges clear the input box, type the text and send Enter as its own keystroke (one text+CR write is a paste and never submits). `--nudge` sends one by hand.
- `hive-watch-guard.sh`: Claude Code Stop hook, opt-in per machine for the session that runs AT. In AT mode it blocks the session from going idle while `hive-triage-watch.sh` isn't running, because the watcher exits on every event and must be relaunched. Add it under `hooks.Stop` in `.claude/settings.local.json` (never the shared settings: a control-panel terminal runs no watcher). Silent where `pgrep` is missing.
- `hive-resume.sh`: the same restart for AT work that is not under the keepalive (an interactive terminal): when `hive_limit_stalled`, it starts one headless resume run and reports to the outbox. Run every 10 min via `launchd/hive-resume.plist.template`.
- `hive-session-prompt.md`, `hive-reserve-prompt.md`: the background and reserve session prompt templates (`{{PLACEHOLDERS}}`).
- `hive-notify.sh <TAG> "<text>"`: appends a tagged line to the outbox.
- `hive-wake-pending.sh`: zero-token check for headless (`claude -p`) sessions; prints new TRIAGE wake text and new `@me` (or TM) lines from `msg-inbox.log` since the last call, exit 1 when nothing.
- `hive-outbox-wait.sh`: main terminal; blocks until the outbox grows, prints the new lines, exits.
- `hive-atlas.sh`: Atlas bookkeeping (`accept`, `closeout`).
- `hive-dupe-check.sh "<keywords>"`: run before filing a ticket; exit 1 means something plausible already exists.
- `launchd/hive-keepalive.plist.template`, `systemd/hive-keepalive.service.template`: run the keepalive at login.
- `windows/`: Git Bash and PowerShell supervisors that replace `screen` (`hive-start.ps1`, `hive-status.ps1`, `hive-stop.ps1`, `hive-install-task.ps1`, `hive-keepalive.ps1` (the always-on headless AT session, the Windows hive-keepalive.sh), `hive-supervise.sh`); see `windows/README.md`.

## Tests
`bash tools/agents/tests/all.sh` runs every offline test (stubbed `gh`, `curl` and Discord; no network, no real state):
`ask`, `beacon-channel`, `dev-idle`, `discord-admin`, `discord-bugs`, `discord-mentions`, `hive-failover`, `hive-join`,
`hive` (hive.sh), `msg-quota` (send budget, 429 backoff, quota marker, token), `msg-beacon` (change-only USAGE, HELLO, peer-silent, listener lock) and `msg-volume1`..`3` (24 h send volume in three 8 h slices): thin wrappers over `msg-quota.sh <part>`, split so each file fits the watchdog on Git Bash, `triage-watch-in-progress`, `control-panel` (control-panel mode guards and banner). `tests/lib.sh` builds the fixture (accounts alice, bob, carol, reserve dave).
